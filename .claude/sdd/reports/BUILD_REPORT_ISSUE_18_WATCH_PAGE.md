### Additional manual verification (beyond the design's test plan)

The DESIGN's own "exact" test sketch covers AT-001..AT-004 plus a non-gating 416 edge case, but exercises neither `GET /api/layers`'s partial-render degradation (Decision 6) nor `_parse_range`'s open-ended/suffix forms (Decision 4). Ran a standalone script (outside the repo, in scratchpad, not committed) directly against the same `TestClient` to independently confirm both:

```text
OK: /api/layers all-present -> 200, all exists=true, plan exists=true
OK: /api/layers partial-render -> 200 (not an error), only adaptive exists=true
OK: /api/video open-ended 'bytes=100-' -> 206, correct Content-Range + body
OK: /api/video suffix 'bytes=-100' -> 206, correct last-100-bytes slice
OK: /api/video nonexistent path -> 400
OK: /api/vtt nonexistent path -> 400
junk.srt -> status 400
ALL MANUAL CHECKS PASSED
```

Confirms: (1) `/api/layers` returns `200` with per-layer `exists` booleans both when all four layers + the plan sidecar are present and when only the adaptive layer exists — a partially-rendered episode never surfaces as an error, exactly Decision 6's intent; (2) `_parse_range`'s open-ended (`bytes=100-`) and suffix (`bytes=-100`) forms compute the correct `(start, end)` and `Content-Range`, not just the single explicit-range form the pytest suite asserts on; (3) an unparseable subtitle file (`/api/vtt`) and a nonexistent path (both `/api/video` and `/api/vtt`) come back as `400`, never a `500`, matching Decision 4/5's error-handling contract.
